# 开发约定

> 整理日期：2026-08-11 ｜ 状态：初版（后续随开发持续完善）
> 定位：统一后续功能搭建方式与注意事项，作为新增代码时的自检清单。
> 适用：斜月安全管理系统（MS_SafetyManagementSystem，个人版 Beta V1.0）
> 关系：本文是"怎么做"的约定；问题清单与改进计划见 `ISSUES.md`；数据存储细节见 `数据架构.md`。

---

## 一、技术栈与分层速览

- **技术栈**：.NET 10（`net10.0-windows10.0.17763.0`）+ WPF + WPF-UI 4.3 + CommunityToolkit.Mvvm + SQLite（Microsoft.Data.Sqlite + Dapper）
- **目录分层**：
  - `Models/` —— 数据实体（Record、PersonnelRecord、Group、Attachment）
  - `Services/` —— 数据访问与业务服务（ProjectDbContext、ProjectDataService、ConfigManager 等）
  - `ViewModels/` —— 视图模型与命令
  - `Views/` —— 通用窗口
  - `Controls/`、`Helpers/`、`Converters/` —— 自绘控件、工具、值转换器
  - 业务模块独立目录：`Hazard/`（隐患）、`Peoplemanagement/`（人员）、`ImageViewer/`（图片查看器）、`Analysis/`（统计）、`Export/`（导入导出）
- **新功能落位顺序**：`Models`（实体）→ `Services`（数据/业务）→ `ViewModels`（命令）→ 模块目录（界面）→ `MenuBar`/`MainWindow` 接线

## 二、代码约定

- 代码注释与 UI 文本一律**中文**。
- 模块名等常量定义在 `Common/Constants.cs`（`ModuleNames.Hazard` / `ModuleNames.Personnel`）。
- 实体扩展字段优先放 `Record.ExtraData`（JSON 字符串），避免频繁加列。
- **大文件用分部类拆分**：参照 `Hazard/RecordCardView.*`（AutoSave / Interactions / Photos / Suggestions）模式，单文件超 1000 行应拆分。
- 服务类命名 `XxxService`，数据库上下文 `XxxDbContext`。
- 全局可用的单例服务经 `Helpers/AppServiceProvider` 提供（如 `SettingsService`）。

## 三、数据层约定（重点）

- **新增列必须同时改两处**：`ProjectDbContext.CreateTablesSql`（新建库建表）**和** `EnsureDatabase()` 的按需 `ALTER TABLE ADD COLUMN`（老库补列）。
  > ⚠️ 2026-08-11 教训：曾只维护了老库补列路径，`CreateTablesSql` 缺列导致**全新环境首次建库**添加分组/记录/附件直接报 `no column named ...`。两条路径缺一不可。
- 全部使用**参数化查询**（Dapper），禁止字符串拼接 SQL。
- 写操作**短连接**：每次操作新建连接，用完即关；项目库启用 WAL 模式。
- 附件 `Attachments.RelativePath` / `ThumbnailPath` 以 `Project_{项目ID}` 开头、相对 **ProjectsDate 根目录**；拼接用 `GetProjectsDateRoot()`；复制卡片用 `RebuildAttachmentPath` 重建路径（替换 Card_ 与年月段）。
- 分组树命名约定（多处正则/解析依赖）：Hazard 顶级=`yyyy年MM月`、子级=`MM月dd日`（可带 Tag）；Personnel 顶级=单位、子级=部门。

## 四、功能搭建流程（写 → 验 → 报）

1. **实现**：按"一、分层落位"完成一个功能闭环（实体 → 服务 → 命令 → 界面 → 接线）。
2. **验证**（适用哪个跑哪个）：
   - `dotnet build` 0 错误；
   - 涉及数据层/纯逻辑：在 `MSpirit.SafetySys.Tests`（xUnit）**补单元测试**，`dotnet test` 全绿；
   - **新库路径（建表/迁移）只有全新库测试能暴露**——测试基类 `TestProject` 每个用例新建库，天然守护建表 SQL，改动建表必须跑数据层测试。
3. **汇报**：一句话说明完成内容与验证结果。

## 五、注意事项（坑清单）

- **成对代码对称修改**：Hazard / Personnel 两套模块代码同构（面板、卡片、导出），改一处必须检查另一侧。
  > 2026-08-10 教训：退出线程异常 bug 因只修 Personnel 侧、漏掉 Hazard 侧而复发。
- **退出流程访问 `Application.Current` 一律 `?.`**：WPF 在 `Shutdown()` 过程中会把 `Application.Current` 置为 null，裸访问会 NRE（`Application.Current?.MainWindow as MainWindow`）。
- **程序退出统一走 `AppExitManager.RequestExit()`**（2026-08-12 起）：禁止在业务代码中直接调用 `Application.Current.Shutdown()` 退出（窗口 `Close()` 会被拦截转为隐藏托盘）。新模块需要退出清理（停止服务、落盘数据等）时，在启动处 `AppExitManager.RegisterCleanup(...)` 登记即可——退出管理器负责防重入、异常隔离与统一调度，模块增多时退出入口无需改动；`App.OnExit` 保留为最终兜底（清连接池 / 退出备份 / 释放单实例 / 关日志）。
- **WPF Shape 的 `Fill="None"` 会运行期抛 XamlParseException"令牌无效"**（2026-08-12 踩坑）：编译期 BAML 生成不报错，运行期 `DeferredBinaryDeserializerExtension` 反序列化时 BrushConverter 不识别 "None" 才炸。**必须写 `Fill="Transparent"`**；`Stroke` 同理不要用 "None"。
- **窗口内容区拖拽统一用 `WindowDragHelper.EnableDrag="True"`**（2026-08-12 定稿）：新窗口要支持"内容区拖拽平移"时，窗口元素加附加属性 + 根 Grid 设 `Background="Transparent"`（null 背景不参与命中测试，空白区拖不动）。实现已内置标题栏排除与交互控件白名单。三个坑：① XAML 事件不能挂静态方法（MC6005）→ 用附加属性；② ListBox/ScrollViewer 内部会消费 MouseLeftButtonDown 冒泡事件 → 必须用 Preview（隧道）；③ 自定义"模拟按钮"（`Border + MouseLeftButtonDown`）会被拖拽吞点击 → 应改用真 `ButtonBase`。
- **LAN/HTTP 服务 `Start()` 必须同步等待 `StartAsync`**（2026-08-12 踩坑）：`_ = _app.StartAsync(...)` fire-and-forget 导致端口绑定失败（IOException）不感知、端口探测永远"成功"、多服务显示同一端口——必须 `Task.Run(() => _app.StartAsync(_cts.Token)).GetAwaiter().GetResult()`，失败清理 `_app` 后重新抛出；调用方 `StartOnAvailablePort` 的 catch 放宽为 `IOException / InvalidOperationException / HttpListenerException`。
- **自绘菜单（DropdownMenu）点击外部关闭用 `Mouse.Capture` + `PreviewMouseDownOutsideCapturedElement`**（2026-08-12 修复）：不要用"找激活窗口挂 PreviewMouseDown"（`Application.Current.Windows.OfType<Window>().FirstOrDefault(w => w.IsActive)`）——独立窗口/托盘打开场景下窗口激活状态不可靠，点击外部不关闭。正统方案：`Mouse.Capture(contentControl, CaptureMode.SubTree)` + `AddHandler(Mouse.PreviewMouseDownOutsideCapturedElementEvent, ...)`（注意是 **Mouse 附加事件，非 UIElement 实例事件**，不能 `+=` 直接挂）；Close 时 `RemoveHandler` + `ReferenceEquals(Mouse.Captured, child)` 判断后 `Mouse.Capture(null)` 释放。
- **打开文件属性对话框用 shell32 `SHObjectProperties`，不要用 `Verb = "properties"`**（2026-08-12 修复）：`new ProcessStartInfo(path) { Verb = "properties", UseShellExecute = true }` 在对象初始化器里 `UseShellExecute` 在 `Verb` 之后赋值，verb 被重置/忽略而静默失败（无弹窗、无异常）。可靠方案：`[DllImport("shell32.dll")] SHObjectProperties(IntPtr.Zero, 0x1 /*SHOP_FILEPATH*/, path, null)`，返回非 0 记日志。
- **不新增空 catch**：统一记录日志（Serilog）+ 必要的用户提示；空 catch 吞异常是已知问题，不要再增加。
- **不引入未接线的半成品代码**：未完成的功能要么完成，要么排除编译并在 `ISSUES.md` 注明（如 `Controls/FluentPopup.cs`、`WindowMaterial.cs` 前例）。
- **新增 NuGet 依赖要谨慎**：影响发布体积；**依赖库版本变化后必须发全量更新包**（增量包不更新依赖 dll，会造成版本混用）。
- **测试隔离**：测试一律用临时目录（`TestProject`），绝不触碰真实 `D:\MSpirit.SafetySys.Date`；测试 helper 不要内部 new 自己的环境再跨对象引用（会 FK 失败）。

## 六、发布与文档约定

- **版本号三处同步 + 按幅度定版**：`MS_SafetyManagementSystem.csproj` 的 `Version` / `AssemblyVersion` / `FileVersion` 三处一致；定版规则见 **`docs/版本号管理方案.md`**（按变更幅度递增、不按日期：微调→第4位、修复/界面→第3位、完整功能模块→第2位、重大/不兼容→第1位；定版时三处同步 = csproj + CHANGELOG 条目标题 + AboutWindow 更新日志文本）。
- **发版链路**：`dotnet publish` 到 `bin\Release\MSpirit.SafetySys` → 双击「其他文件」的打包脚本（全量/增量）→ 分发 `.msupd` + `Updater.exe`（详见 `更新器使用说明.md`）。
- **全量 vs 增量**：依赖库未动 → 增量包（`打包增量更新包.bat`，默认 4 个主程序文件）；依赖库变动/跨版本大改 → 全量包（`打包全量更新包.bat`）。
- **文档边界**（2026-08-13 确认完整规则）：
  - `docs/` = **正式项目文档**（进 git、随仓库分发；如《数据架构》《开发约定》《版本号管理方案》）
  - `临时文档/` = **非正式/时效性/计划类文档**（功能开发备忘、发布清单、问题分析等；**未形成正式 Skill 的文档一律放这里**；已被 .gitignore 排除）
  - `Skills/` = **正式 Skill 归档**（仅放已形成的标准 SKILL.md 格式技能——frontmatter 含 name + 触发描述；2026-08-13 起；当前仅 `wpf-partial-class-split.SKILL.md`；WorkBuddy 自动加载的技能正本在技能目录 `~/.workbuddy/skills/`）
  - `其他文件/` = 打包脚本（make_*.py / 打包*.bat）与测试图片等工具类（脚本路径约定不变）
- **变更同步**：数据表结构/目录调整 → 同步 `数据架构.md`；功能完成/Bug 修复 → 更新 `ISSUES.md`（含修复记录）；新增约定 → 补本文档。

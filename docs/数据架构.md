# 数据架构

> 适用范围：斜月安全管理系统（MS_SafetyManagementSystem）
> 说明：本文描述系统的数据存储位置、数据库表结构、附件目录布局与路径规则，是排查数据问题、做备份/迁移时的依据。数据定义以代码为准（`Services/ProjectDbContext.cs`、`Services/MasterDbContext.cs`、`Services/DataPathService.cs`）。

## 1. 数据根目录

数据根目录由 `Services/DataPathService.cs` 决定：

- 机器存在可用的 D 盘时：`D:\MSpirit.SafetySys.Date`
- 否则：`%LOCALAPPDATA%\MSpirit.SafetySys.Date`

### 根目录结构

```
MSpirit.SafetySys.Date/
├── MappingDictionary.json       # 字段别名映射配置（2026-08-10 从 Data\ 上移至此）
├── CommonHazardTypes.json       # 常用隐患类型配置
├── FavoriteLinks.json           # 收藏链接配置
├── ViewState.json               # 视图状态（上次选中节点/滚动位置等）
├── ProjectsDate/                # 项目数据区（主库 + 各项目，2026-08-10 起主库也在此）
│   ├── master.db                # 主数据库（项目列表 + 全局设置）
│   └── Project_{项目ID}/
│       ├── data.db              # 项目数据库（唯一）
│       ├── Cache/               # 项目级缓存（图片缩略图等）
│       ├── Hazard_{yyyy-MM}/    # 隐患附件（按月分目录）
│       │   └── Card_{记录ID}/
│       │       ├── Hazard-1_xxx.jpg
│       │       ├── Remedy-1_xxx.jpg
│       │       └── thumb/       # 缩略图
│       └── Personnel_{单位分组ID}/  # 人员附件（按单位分目录）

├── ProjectsCache/               # （历史遗留空目录）
└── ProjectsDate.Backup/         # 自动备份目录（2026-08-10 起）：Backup_时间戳\ 内含 master.db + 配置 json + 各项目 data.db，保留 30 天 + 最多 100 份轮换
```

> **注意（2026-08-10 目录调整）**：`master.db` 由 `Data\master.db` 移入 `ProjectsDate\master.db`；`MappingDictionary.json` 由 `Data\` 上移至数据根；`Data\` 目录已废弃。改动涉及 `MasterDbContext`、`MappingDictionaryService`、`DataPathService`、`App.xaml.cs`（退出清理）、`ThumbnailMigration`（顺带修正路径错配）。

### 备份范围

完整备份 = 整个数据根目录（应用退出状态下复制即可），重点为 `ProjectsDate\master.db`、`ProjectsDate\` 与各 json 配置文件。

程序内置的**自动备份机制**（启动/退出自动备份、保留 30 天最多 100 份、只备数据库不备图片）详见「8. 自动备份机制」。

## 2. 主数据库 master.db

路径：`{数据根}\ProjectsDate\master.db`（2026-08-10 起，此前为 `Data\master.db`），由 `MasterDbContext` 管理。

### Projects 表

| 列 | 类型 | 说明 |
|---|---|---|
| Id | TEXT PK | 项目 ID（GUID N 格式） |
| Name | TEXT NOT NULL | 项目名称 |
| Created | TEXT NOT NULL | 创建日期 |
| SortOrder | INTEGER NOT NULL | 排序（项目管理界面顺序） |

### Settings 表

| 列 | 类型 | 说明 |
|---|---|---|
| Key | TEXT PK | 设置键 |
| Value | TEXT NOT NULL | 设置值 |

常用键：`CurrentProjectId`、`CurrentModule`（Hazard/Personnel）、`ImageViewerType`、`ImageViewerStartMode`、`HazardTypeSelectorMode`（FullWindow/DropdownMenu）、`WindowBounds`。

## 3. 项目数据库 data.db

## 4. 附件文件布局与路径规则

### 目录约定

- 隐患模块：`Project_{项目ID}\Hazard_{yyyy-MM}\Card_{记录ID}\{文件名}`
- 人员模块：`Project_{项目ID}\Personnel_{单位分组ID}\Card_{记录ID}\{文件名}`
- 缩略图统一放在卡片目录的 `thumb\` 子目录，文件名为原图名加 `_thumb` 后缀（如 `Hazard-1_xxx_thumb.jpg`）。
- 原图文件名格式：`{类型}-{序号}_{GUID}.jpg`（界面内保存时经 `ImageHelper` 统一输出 JPG；局域网 OCR 录入的证件照可能保留原始格式，如 `idcard_1_xxx.png`）。

### RelativePath 规则（重要）

- `Attachments.RelativePath` / `ThumbnailPath` 以 **`Project_{项目ID}` 开头**（含 `\` 分隔符），是相对于 **ProjectsDate 根目录** 的相对路径。
- 拼接完整路径时使用 `ProjectDataService.GetProjectsDateRoot()`（= `ProjectsDate`），即 `ProjectsDate + RelativePath`。
- 复制卡片时用 `RebuildAttachmentPath` 重建目标路径：替换 `Card_{源ID}` → `Card_{目标ID}`，并替换年月段 `{模块}_{yyyy-MM}` → 目标年月（从目标分组推导，`GetYearMonthFromGroupId`）。

### 示例

```
RelativePath = Project_{项目ID}\Hazard_{yyyy-MM}\Card_{记录ID}\Hazard-1_{图片ID}.jpg
完整路径     = D:\MSpirit.SafetySys.Date\ProjectsDate\ + RelativePath
```

## 5. 分组树命名约定

- **隐患模块**：两级树。顶级 = 年月（`2026年07月`），子级 = 日期（`07月03日`，可带标签 Tag）。
- **人员模块**：两级树。顶级 = 单位（`XX建设` 等），子级 = 部门/班组（`XX班组`）。
- 年月与 `YearMonth`（`yyyy-MM`）互相转换：`GetYearMonthFromGroupId` 从分组名正则解析 `(\d{4})年(\d{1,2})月`。

## 6. 数据一致性注意事项

- **SQLite WAL 模式**：项目库启用 WAL；写操作短连接，每次操作新建连接。
- **Busy 重试**：`DatabaseHelper.ExecuteWithRetry` 对 `SQLITE_BUSY`（错误码 5）重试 3 次、间隔 100ms；仅部分更新操作走该包装，其余为直接执行。
- **删除行为**：删除记录会级联删除附件数据库行（外键 ON DELETE CASCADE）与物理文件（尽力而为，文件删除失败仅记日志）。
- **历史数据**：项目库中可能存在附件 DB 行存在但物理文件缺失的情况（复制卡片时会提示"图片文件缺失"）。
- **日志**：程序目录 `logs\debug*.log`，按天滚动保留 7 天；`UI线程异常` 也会写入日志（`App.xaml.cs` 全局处理器）。

## 8. 自动备份机制

> 原独立文档《自动备份机制.md》于 2026-08-13 并入本节，实现组件 `Services/BackupService.cs`。
> 定位：程序崩溃 / 数据库损坏 / 误删时的事故兜底，保证数据可恢复（对应 ISSUES 原第 5 条，2026-08-10 已实现并验证）。

### 8.1 定位与目标

1. **防程序性问题**：data.db 损坏、误删、程序崩溃写坏 —— 数据库是唯一"程序自己会搞坏"的东西。
2. **不防物理灾难**：磁盘损坏、整盘丢失属于物理灾难，同盘备份防不住（备份与数据同盘一起坏），需靠定期拷 U 盘/网盘。
3. 恢复方式：手动拷回备份文件（恢复界面列为二期）。

### 8.2 核心决策：只备数据库，不备图片

**备份内容 = master.db + 各项目 data.db + 配置 json（MappingDictionary / CommonHazardTypes / FavoriteLinks / ViewState），不备份图片附件。**

| 内容 | 实测大小 | 占比 |
|------|---------|------|
| 图片附件（隐患照/整改照/证件照） | ~493MB | 99.8% |
| 数据库（master.db + 各项目 data.db + 配置 json） | ~1MB | 0.2% |
| 缩略图 thumb | ~4MB | 可重建，排除 |

- **只备数据库即可完整恢复**：data.db 损坏 → 拷回数据库备份 → 库内 `RelativePath` 仍指向磁盘上完好的原图 → **记录 + 图片完整恢复**。
- 备份图片的价值仅在于"图片文件本身被删/磁盘坏"——该场景同盘备份同样失效，备份图片反而白白付出数百 MB × N 份的成本。
- 不做压缩（量小裸复制最可靠）、不做增量（1MB/份全量瞬时完成）、不做定时备份（个人版风险窗口无必要）。

### 8.3 备份目录结构

```
MSpirit.SafetySys.Date\
├── ProjectsDate\                        ← 项目数据区
│   ├── master.db                        ← 头库
│   └── Project_{id}\data.db             ← 各项目库
└── ProjectsDate.Backup\                 ← 备份根（数据根内，与 ProjectsDate 平级）
    ├── Backup_20260810_201100123\       ← 单份备份（时间戳含毫秒）
    │   ├── master.db                    ← 头库
    │   ├── MappingDictionary.json       ← 字段别名映射
    │   ├── CommonHazardTypes.json       ← 常用隐患类型
    │   ├── FavoriteLinks.json           ← 收藏链接
    │   ├── ViewState.json               ← 视图状态
    │   └── Project_{id}\data.db         ← 各项目库（保持相对结构）
    ├── Backup_…（更早）
    └── …（保留最近 30 天 + 最多 100 份，超出删最旧）
```

- 备份放**数据根内**：备份跟着数据走——整体拷贝数据根到新电脑/U 盘时备份自动带走，不易遗漏。
- 图片附件、缩略图/Cache/Temp **不备份**（见 8.2，后者可再生）。

### 8.4 触发时机与保留策略

**触发时机：启动 + 退出，双保险**

| 时机 | 模式 | 作用 |
|------|------|------|
| **启动时**（主窗口显示后后台静默） | **在线备份**（SQLite BackupDatabase） | 兜底：上次异常退出（崩溃/断电）没走到退出备份时，本次启动补上 |
| **退出时**（OnExit 清理连接池之后） | **关库后直接 File.Copy** | 主备份：覆盖当天全部数据，最新状态 |

- 启动用在线备份：程序刚启动、数据库可能正被占用，在线备份生成一致快照（WAL 一并包含），不打断程序；`SqliteConnection.BackupDatabase` 源库 → 临时文件（`Pooling=False`，防止句柄被池持有）→ 拷入备份目录。
- 退出用直接复制：OnExit 已 ClearPool 所有库连接 → 文件无占用、WAL 已合并 → 复制最可靠。
- 配置 json 直接 File.Copy（KB 级，无并发写）。

**保留策略（时间为主 + 份数封顶双保险）**
- 保留最近 **30 天**，超过自动删除（时间戳从目录名解析 `Backup_yyyyMMdd_HHmmssfff`）。
- 最多 **100 份**，超出按时间倒序保留最新 100 份（防异常高频备份爆盘）。每份约 1MB，最坏 ≈ 100MB。
- 目录名**含毫秒**：防止同秒内多次备份（如快速重启）撞同一目录导致覆盖。

**恢复方式（本期）**：手动把 `Backup_xxx` 里的文件按原路径拷回（master.db → `ProjectsDate\`、json → 数据根、Project_x\data.db → `ProjectsDate\Project_x\`）；恢复界面（选时间点 → 校验 → 覆盖恢复）列为二期。

### 8.5 数据根"请勿手动操作"提示文件

- 程序在数据根目录放一个**无扩展名**提示文件，文件名即提示语：`此目录为斜月安全管理系统存档目录，请勿手动操作`。
- 无扩展名（不用 `.txt`）：避免被文件类型图标掩盖文件名、避免用户习惯性双击打开。
- 幂等创建（`DataPathService.EnsureDataRootNoticeFile()`，MainWindow Loaded 后台执行，已存在绝不覆盖）；老用户升级后首次启动自动补上。
- **隐藏价值**：数据根搬迁/手动备份时，该文件是天然的"这目录是我的"标识，可用于校验备份源目录正确。

# 版本号管理方案

> 定稿日期：2026-08-12
> 适用范围：斜月安全管理系统（MS_SafetyManagementSystem）全部分发版本
> 核心思想：**按变更幅度定版本号，不按日期递增**（开发时间不固定，版本号只反映"一批变更的规模"）

## 一、版本号结构

沿用 .NET 四段式：`主版本.功能版本.修订版本.微调版本`。版本数值的**唯一来源是根目录 `Directory.Build.props` 的 `SafetySysVersion`**，主程序 / 启动器 / 更新器三个工程的 `Version` / `AssemblyVersion` / `FileVersion` 全部由它注入（2026-10-17 起）。

```
1 . 1 . 0 . 0
│   │   │   └── 微调号：很小、数量少的变更
│   │   └────── 修订号：Bug 修复、界面调整、多个小改进的一批
│   └────────── 功能号：新增完整功能模块/工具（对用户可见的新能力）
└────────────── 主版本：重大重构、数据不兼容、里程碑定档发布
```

## 二、各段位触发条件

| 段位 | 名称 | 触发条件 | 示例（项目真实历史） |
|---|---|---|---|
| 第 4 位 | 微调号 | 很小、**数量少**的变更：文案调整、单个小修、单点界面微调、局部优化 | `1.1.0.1`（如按钮文案调整、单处 bug 小修） |
| 第 3 位 | 修订号 | **Bug 修复、界面调整**、多个小改进凑成的一批——**日常开发的主要版本单位** | `1.0.1.0`（使用提示/关于窗口 + 备份修复 + 打包基建，2026-08-11） |
| 第 2 位 | 功能号 | **新增完整功能模块/工具**（对用户可见的新能力，如新工具窗口、新菜单体系）；小窗口（如使用提示）不算，归第 3 位 | `1.1.0.0`（手机图片传输完整模块 + 托盘多级菜单 + 统一退出管理器，2026-08-12） |
| 第 1 位 | 主版本 | 重大重构、数据结构不兼容（老数据无法直接打开）、里程碑定档发布（如正式版 V1.0） | `2.0.0.0` |

## 三、递增规则

1. **一批变更一次性定版**：不按日期、不逐条递增；一批变更完成后准备发版时，按该批内**最高幅度**确定升哪一段。
2. **递增某段位时，右侧低位全部归零**：
   ```
   1.1.0.0 → 微调一批   → 1.1.0.1
   1.1.0.1 → 修复一批   → 1.1.1.0
   1.1.1.0 → 新功能模块 → 1.2.0.0
   1.2.0.0 → 定档正式版 → 2.0.0.0（如适用）
   ```
3. **幅度判定以"对用户的影响"为准**：用户能感知的新能力 → 功能号；用户感知到的"坏了/变样了"→ 修订号；用户几乎无感知的小调整 → 微调号。

## 四、定版时机与同步

- 定版时机：**一批变更完成、准备制作更新包时**确定版本号。
- 定版时改齐四处（**数字只改 1 处，其余是不能继承的静态文本**）：
  1. **根 `Directory.Build.props` 的 `SafetySysVersion`** —— 唯一数字来源；改这里，主程序、绿色版启动器（`斜月安全管理系统.exe`）、`Updater.exe` 三者 exe 属性里的版本号同时跟随，无需逐个工程改；
  2. `MSpirit.SafetySys.Package\AppxManifest.xml` 的 `Identity/@Version` —— MSIX 清单是静态 XML，读不到 MSBuild 属性，必须手工同步（第 4 段按商店要求固定为 0）；
  3. `CHANGELOG.md` 对应条目标题（`## [x.y.z.w] - 日期`）；
  4. `AboutWindow`（关于软件 → 更新日志）的 `BuildChangelogText()` 文本。
- 各工程 csproj **不再**写 `Version` / `AssemblyVersion` / `FileVersion`（写了会覆盖 props 注入值，等于制造第二个来源）。
- README 等文档中的版本号：定档发布时统一更新（见开发约定"版本号管理约定"）。

## 五、与更新包类型的联动

版本号段位作为发包类型的**参考信号**（实际仍以"依赖库是否变化"为最终判断，见开发约定.md）：

| 段位变化 | 发包倾向 | 理由 |
|---|---|---|
| 第 1、2 位 | **全量包** | 新功能/重大变更常伴随依赖库、资源文件变动 |
| 第 3、4 位 | **增量包** | 仅主程序文件变化，依赖未动 |

## 六、历史归类（2026-08-12 重新归类）

新方案实施时对既有历史版本按幅度重新归类：

| 原版本号 | 新版本号 | 归类依据 |
|---|---|---|
| 1.0.0.0（首个内测版） | 1.0.0.0 | 保持不变（里程碑起点） |
| 1.0.0.1（2026-08-11） | **1.0.1.0** | 使用提示/关于窗口 + 备份/建表修复 + 测试与打包基建 → 修订号 |
| 1.0.0.2（2026-08-12） | **1.1.0.0** | 手机图片传输完整模块 + 托盘多级菜单 + 关闭程序 + 统一退出管理器 → 功能号 |
| 1.1.0.0（2026-08-12） | **1.2.0.0** | 标注与剪裁 + 图片剪裁完整实现 + 数据根保护 + LAN 强化 → 功能号（2026-08-17） |

> 注：1.0.0.1 / 1.0.0.2 为按日期逐日递增的旧习惯产物；自本方案定稿起不再按日期递增，一律按上述幅度规则定版。
